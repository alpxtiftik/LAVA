# LAVA: Local AI Vulnerability Auditor

LAVA is an AI-powered vulnerability validation pipeline designed to filter out the high volume of "False Positive" noise generated by static firmware analysis tools like EMBA. 

Instead of fine-tuning a model, LAVA uses an In-Context Learning (ICL) approach. It parses static findings (e.g., hardcoded credentials), extracts relevant contextual files directly from the firmware's filesystem, and feeds this enriched data to a locally running LLM (Large Language Model) like `llama3`. The AI logically analyzes the evidence and classifies each finding as either a genuinely exploitable vulnerability (**True Positive**) or an inactive/unusable artifact (**False Positive**).

## Features
- **Zero-Data-Leak Local AI:** Fully relies on locally hosted models (via Ollama) ensuring sensitive firmware files never leave your machine.
- **Smart Enrichment:** Doesn't just look at the line of code. Extracts surrounding code blocks and metadata to give the AI proper context.
- **Iterative Saving:** Safe from crashes. Saves results iteratively so you never lose your progress during a long analysis.
- **Cross-Platform Native Desktop App:** A fully compiled desktop GUI application (Windows, Linux, macOS). Features a built-in interactive dashboard to search, filter (by True/False Positives and Dynamic Modules), and read the AI's reasoning.
- **Native Folder Browser:** Start and stop LAVA scans directly from the UI using your OS's native folder selection dialog.

## Prerequisites
- **Ollama:** Installed and running locally (e.g., `ollama serve`).
- **Llama3 Model:** Pulled via Ollama (`ollama pull llama3`).

### For End-to-End Pipeline (Firmware Scanning)
If you want LAVA to also run EMBA for you automatically, you need:
- **Linux:** EMBA installed natively (e.g., Ubuntu/Kali).

> **Note on Windows (WSL):** Due to strict kernel module requirements by firmware extraction tools (like `nandsim`, `ubi`, `ufs`), running the "Full Pipeline (EMBA Scan)" on Windows via WSL is **not supported and disabled**. Windows users must run EMBA on a native Linux host, transfer the log directory to their Windows machine, and use LAVA in **"Analyze EMBA Log Directory"** mode.

*(Optional if running from source)*
- Python 3.11+
- `pip install -r requirements.txt`

## Configuration
1. Clone this repository.
2. Update your configuration in `config/ai_config.env`:
   ```env
   LOCAL_AI_IP="127.0.0.1"
   LOCAL_AI_PORT="11434"
   LOCAL_AI_MODEL="llama3"
   
   # EMBA Path (For End-to-End Pipeline on Linux)
   # On Linux: /path/to/emba/emba
   EMBA_PATH="/path/to/emba/emba"
   ```

## Usage

### 1. The Desktop Application (Recommended)
You can manage the pipeline natively from the UI. 

**Windows:**
Compile the application using the build script:
```powershell
.\scripts\build_ui.ps1
```
Then double-click `LAVA_UI.exe` to launch.

**Linux / macOS (Plug-and-Play):**
No compilation needed. Simply run the startup script, which will automatically configure a virtual environment, install dependencies, and launch the UI:
```bash
bash scripts/start_linux.sh
```

**Using the UI:**
1. You will see a Mode Toggle at the top:
   - **Analyze EMBA Log Directory:** Provide the path to a completed EMBA log directory. LAVA will run AI analysis on it. (Available on Windows and Linux).
   - **Full Pipeline (Scan Firmware):** Select a `.bin` or `.tar` firmware file. LAVA will automatically launch EMBA to scan the firmware and immediately begin AI analysis on the results. *(Linux Only)*
2. Click **Browse (📁 Select)** and select your file or folder.
3. Click **Start Scan**. The UI will show a real-time status, display an embedded terminal for live logs, and automatically populate findings once they are analyzed.

### 2. Automated CLI Pipeline
If you prefer running the orchestration scripts from the terminal instead of the GUI:

**To scan a firmware file (Full Pipeline - LINUX ONLY):**
- **Linux:**
  ```bash
  bash scripts/run_emba_lava.sh -FirmwarePath "/home/user/firmware.bin" -LogDir "/home/user/lava_logs"
  ```

**To analyze an existing EMBA log (Available on All OS):**
- **Windows:**
  ```powershell
  .\scripts\run_lava.ps1 -LogDir "C:\path\to\emba_log"
  ```
- **Linux:**
  ```bash
  bash scripts/run_lava.sh -LogDir "/path/to/emba_log"
  ```

### 3. Manual Pipeline
If you prefer to run the steps manually:
```bash
# 1. Parse raw EMBA logs
python src/core/parser.py --log-dir "emba_iotgoat_log" --out findings.json --merged-out merged_findings.json

# 2. Enrich findings with actual file context
python src/core/enricher.py --merged merged_findings.json --log-dir "emba_iotgoat_log" --out enriched_findings.json

# 3. Classify using Local AI
python src/core/classifier.py --mode run --config config/ai_config.env --ground-truth ground_truth.json --enriched enriched_findings.json --out verdicts.json
```
